# Данные и показательные проверки

## Готовый синтетический набор

Команда `netgaf demo <новая_папка>` и кнопка «Создать демоданные» формируют:

| Файл | Сценарий | Что меняется |
|---|---|---|
| normal.pcap | Нормальный трафик для обучения | Небольшие колебания пакетов и размеров, порты 80/443 |
| packet_burst.pcap | Всплеск интенсивности | 55 пакетов/с вместо примерно 3–9, привычные порты и размеры |
| byte_surge.pcap | Рост объёма | Прежнее число пакетов, полезная нагрузка 1200 байт |
| port_diversity.pcap | Обращения к большему числу служб | Разные порты назначения, прежние размеры/интенсивность |
| mixed.pcap | Три изменения последовательно | У каждого сценария собственный временной интервал |

Каждый захват длится около 640 секунд. Последний неполный интервал исключается;
при окне 32 и шаге 16 получается 39 окон на тестовый файл. В отдельных сценариях
изменение действует в [256, 384) с. Смешанный захват: [128,224), [288,384), [448,544) с.
Файл `labels.json` содержит абсолютные UTC-границы и правило разметки.

Обучение использует только `normal.pcap`. Случайные последовательности тестовых
файлов отличаются от обучения. Метка окна равна 1 при любом положительном пересечении
с интервалом изменения для размеченного узла. Правило задаётся до оценки.
Порог не оптимизируется на сценариях. TP/FP/TN/FN и метрики считаются по окнам.
Перекрывающиеся окна статистически зависимы; независимыми наблюдениями их считать нельзя.

Это изменения статистики, а не доказательство наличия реальной атаки. При высокой
легитимной нагрузке также возможны срабатывания. Автоэнкодер выдаёт степень
отклонения и не классифицирует типы атак.

`evaluate-demo` сохраняет Precision, Recall, F1, FPR, трапецеидальную PR-AUC и
Average Precision. Неопределённое отношение при нулевом знаменателе равно `null`.
PR-AUC и Average Precision рассчитаны отдельно, с объединением одинаковых оценок.

## Предлагаемый реальный датасет

Основной кандидат — **CIC-IDS2017**, согласующийся с НИР:
[страница Canadian Institute for Cybersecurity](https://www.unb.ca/cic/datasets/ids-2017.html).
Нужны исходные PCAP и описание сценариев/метки; агрегированные CSV не заменяют
последовательности событий для выбранного конвейера.

Для первого эксперимента предлагается ограниченный набор:

1. Нормальный период понедельника — обучение и отдельная калибровка по времени.
2. Отдельный нормальный период другого захвата — проверка ложных тревог при сдвиге условий.
3. Периоды DoS/DDoS — отклонения интенсивности и объёма.
4. Период PortScan — разнообразие портов. Сканирование многих адресов одного порта
   выбранными тремя признаками может не выявляться.

Необходимо сопоставить направления, IP-узлы и время PCAP с метками. Часовой пояс
описания атак должен быть переведён в UTC явно. Наличие атакующей записи в файле
не делает все узлы и все окна файла аномальными. До вычисления итоговых метрик
нужно зафиксировать соответствие меток окнам и проверить качество разметки.

У исходного CIC-IDS2017 описаны проблемы; для научной оценки следует проверить
исправления **LYCOS-IDS2017** (Rosay et al., DOI: 10.1145/3486622.3493973).
Исправленные потоковые данные требуют проверки совместимости с пакетными метками.
Разметчик реального датасета в прототип пока не включён.

Полный многогигабайтный набор автоматически не скачивается. На этапе разработки
достаточно выбранных временных участков с подтверждёнными метками и происхождением.
Доступность страницы и актуальных ссылок загрузки ещё нужно подтвердить:
в этой облачной сессии запрос к `www.unb.ca` получил отказ сетевого прокси 403.
Это ограничение загрузки источника; локальные демонстрационные проверки работают.

## Следующие эксперименты для ВКР

- Сравнить GASF, GADF, MTF и числовой baseline на одних и тех же событиях.
- Оценить Precision/Recall/F1/FPR/PR-AUC на независимых реальных тестовых периодах.
- Измерить задержку, скорость обработки и память.
- Сравнить окна 16/32/64, дискретизацию, перекрытие и вклад каждого канала.
- Сохранять ошибки и пропуски; не менять параметры по итоговому тесту.
